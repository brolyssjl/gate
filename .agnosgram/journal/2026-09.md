## 2026-09-05 22:30 · gate · fix/tz-test-race-43
- **Did:** Completed gate run "Fix TZ env-var race in agnosgram_write tests (#43)" (2026-09-05-fix-tz-env-var-race-in-agnosgram-write-tests-43, profile bugfix)
- **Learned:** The 2026-08-24 fix's own comment on AGNOSGRAM_BIN_LOCK called a same-value TZ=UTC race "harmless" - true for the overlap of two with_tz calls, but not at the edges: the thread whose own restore first observes TZ unset can have that restore raced by an unrelated third test's restore landing mid-window, on a machine whose ambient zone isn't UTC. Reproduced it directly (see debug-log.md) rather than trusting the issue's description alone.
- **Decided:** When a test needs a fixed local-time zone, parameterize the offset into the function under test instead of mutating the process-global TZ env var - cargo test's parallel unit-test threads share one process, so any process-global env mutation in a test is a latent race, not just the ones that use differing values.
- **Avoid:** Don't assume a comment that says a shared-env-var race is "harmless" still holds once a second dimension (a different env var, or process startup state) changes - re-derive the harmlessness argument for the new case instead of extending it by analogy.
- **Source:** .gate/runs/2026-09-05-fix-tz-env-var-race-in-agnosgram-write-tests-43

## 2026-09-23 08:48 · gate · fix/trust-local-store
- **Did:** Completed gate run "trust-local-store: move TOFU trust out of the repo" (2026-09-22-trust-local-store-move-tofu-trust-out-of-the-rep, profile bugfix)
- **Learned:** Interactively running gate check/gate next in this worktree without GATE_CONFIG_DIR set spawned the full cargo test suite as a child process with the real environment, so in-process unit tests in files this task didn't own (playbooks.rs, gates/*.rs, update.rs, git.rs) resolved the machine-local trust dir to the real $HOME/.config/gate and left ~145 throwaway trust records there - only caught because the coordinator asked for an explicit before/after diff of that directory.
- **Decided:** When a fix changes where a crate-wide public function resolves its state from disk, give it a cfg(test)-only fallback to an isolated location before trusting any pre-existing in-process unit test elsewhere in the crate to stay hermetic - don't rely on every call site remembering to inject an override.
- **Avoid:** Don't assume setting GATE_CONFIG_DIR on my own top-level `cargo test` invocation covers everything; any command that spawns cargo test as a *child* of an unprefixed process (a gate command's own build/test check, a shell script) inherits whatever environment that parent had, not the one I remembered setting three commands ago.
- **Source:** .gate/runs/2026-09-22-trust-local-store-move-tofu-trust-out-of-the-rep
